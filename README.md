## Selected work

### [HERMES — embedded runtime and control plane](https://github.com/kkrafvyn/hermes)

An experimental platform for managing applications across MCU nodes, with C/C++ runtime components, a Python control plane, device agents and a browser dashboard.

- Explore scheduling, checkpointing, migration, application lifecycle and device communication.
- Board configurations include STM32, Nordic and Espressif targets; configuration, host simulation and physical board validation are separate stages.
- Start with the [quickstart](https://github.com/kkrafvyn/hermes/blob/main/docs/QUICKSTART.md) and [architecture](https://github.com/kkrafvyn/hermes/blob/main/docs/ARCHITECTURE.md).

### [KrafGPU-X1 — VHDL architecture model](https://github.com/kkrafvyn/KrafvynGPU)

A VHDL-2008 GPU architecture study with compute, memory, scheduling and peripheral modules, plus a GHDL simulation runner and module testbenches.

- Review the [RTL](https://github.com/kkrafvyn/KrafvynGPU/tree/master/krafgpu_x1_vhdl_final/krafgpu_x1_vhdl/rtl) and [unit testbenches](https://github.com/kkrafvyn/KrafvynGPU/tree/master/krafgpu_x1_vhdl_final/krafgpu_x1_vhdl/sim/unit).
- The chip specifications are architectural targets. They are not measured silicon performance or proof of FPGA implementation.

### [Media Extensions — full-stack commerce application](https://github.com/kkrafvyn/MediaExtensions)

A React/TypeScript storefront and staff application with an Express API and PostgreSQL data layer.

- Product ordering, repair booking, role-based staff workflows, digital delivery and payment integration.
- Inspect the [API routes](https://github.com/kkrafvyn/MediaExtensions/tree/main/server/src/routes), [client pages](https://github.com/kkrafvyn/MediaExtensions/tree/main/client/src/pages) and [tests](https://github.com/kkrafvyn/MediaExtensions/tree/main/server/src/tests).
- [Deployment guide](https://github.com/kkrafvyn/MediaExtensions/blob/main/VERCEL.md).

### [Sepsis monitor — KiCad schematic study](https://github.com/kkrafvyn/sepsis-monitor-kicad)

A hierarchical sensor-monitoring schematic exploring power, MCU, sensing and isolation/fail-safe blocks.

- The README records the circuit decisions, placeholder parts and validation limits.
- This is a schematic study, not a clinically validated device or a manufactured PCB.

## How I approach projects

I prefer a small, paid discovery milestone when requirements or hardware constraints are uncertain. I work toward explicit acceptance criteria, reproducible setup, focused tests and a clear source-code handoff.

The repositories distinguish implemented code, simulation or prototype evidence, and planned capabilities. For hardware work, equipment, board access and physical validation are agreed before committing to delivery dates.
